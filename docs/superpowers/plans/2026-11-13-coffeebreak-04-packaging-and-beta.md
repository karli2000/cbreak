# Coffee Break, Plan 4: Packaging and friends beta

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Coffee Break installable by invited friends from the public GitHub repo, and run a friends-only beta on the free tier.

**Architecture:**
- **Install path:** this repo becomes a Claude Code plugin marketplace. A root `.claude-plugin/marketplace.json` lists the plugin at `./plugin`, so friends run `claude plugin marketplace add karli2000/coffeebreak` and then `claude plugin install coffeebreak@coffeebreak`.
- **Helper runtime:** the helper ships as one committed, pre-bundled JavaScript file (`plugin/dist/coffeebreakd.js`, supabase-js included) and runs with the user's Bun. If Bun is missing, the mod explains how to get it.
- **Invite gate:** the repo is public, so access is gated in Postgres. While invite-only is on (the default), only GitHub accounts on an admin-managed allowlist can create a profile. Admins manage the list on the moderator site.
- **Docs:** README (install, how it works, privacy), MIT license, and a beta runbook.

**Tech Stack:** Bun (`bun build --target=bun`), Claude Code plugin marketplace (2.1.322), Supabase Postgres + pgTAP, the React moderator site, GitHub REST API (`GET /users/{login}` from the browser, public).

**Spec:** `docs/superpowers/specs/2026-11-11-coffeebreak-design.md` §4.2 (layout, marketplace), §4.6 (privacy), §5.1 (setup), §6 (hosting), §8 steps 9–10. **Also read:** `CLAUDE.md` (all sections), `docs/deploy.md`, `docs/moderator-site.md`.

## Global Constraints

- **Owner decisions (2026-11-13):**
  - Public repo plus an invite allowlist.
  - The helper requires Bun; no compiled binaries in v1.
  - License: MIT, `Copyright (c) 2026 Max Kossatz`.
- **Install IDs:** marketplace name `coffeebreak`, plugin name `coffeebreak`, install id `coffeebreak@coffeebreak`. The entry name and `plugin.json` `name` are identical.
- **Plugin version:** `plugin.json` `version` becomes `0.2.0` (users stay on a version until it changes). Every later user-visible release bumps it.
- **Bun:** ≥ 1.2. The mod looks for `bun` on `PATH` first, then at `$HOME/.bun/bin/bun`. When neither exists, setup and break start show exactly: `Coffee Break needs Bun. Install it with: curl -fsSL https://bun.sh/install | bash — then restart Claude Code.`
- **The helper bundle is committed:**
  - `plugin/dist/coffeebreakd.js` is generated by `bun run helper:bundle` (`bun build plugin/helper/main.ts --target=bun --minify --outfile plugin/dist/coffeebreakd.js`).
  - A test fails when the committed bundle differs from a fresh build, so a stale bundle never ships.
  - In dev, `COFFEEBREAK_HELPER_SRC=1` makes the mod run `plugin/helper/main.ts` instead.
- **Invite gate rules:**
  - `public.beta_settings.invite_only` defaults to `true`.
  - A **first** `claim_nickname` (profile creation) raises `not_invited` unless the caller's GitHub id is in `public.beta_invites`. Callers without a GitHub id (email sign-ups) are refused while invite-only is on.
  - Existing profiles are never affected, and removing an invite never removes a profile.
  - Banned GitHub ids stay refused (`banned` is checked first, as today).
- **`not_invited` copy** (plugin setup): `Coffee Break is invite-only right now. Ask the person who invited you to add your GitHub account, then run /coffee setup again.`
- **Site CSP:** `connect-src` adds `https://api.github.com` and nothing else.
- **Public-repo hygiene:**
  - Never commit service-role or secret keys, `.env` files, access tokens, or logs.
  - `scripts/prepublish-audit.sh` scans the working tree and the full history and must pass before the repo goes public.
- **Production changes are owner steps:** `db push --remote`, `site:deploy`, repo visibility, GitHub settings, and inviting people. Never run `bunx supabase config push`.
- **Workflow:**
  - Work test-first, and keep `CLAUDE.md` current in every task.
  - Commits end with a `Co-Authored-By:` trailer.
  - Never push unless the owner asks.

## Review Focus

1. **A friend installs from the marketplace on a machine with Bun only at `~/.bun/bin`** (not on Claude Code's `PATH`). The helper must still start. → Task 3 test `finds bun in ~/.bun/bin when PATH has none`.
2. **An uninvited GitHub user runs `/coffee setup`.** They get the `not_invited` copy, can retry after being invited, and are never left half set up. → Task 1 pgTAP `uninvited first claim is refused, invited succeeds`, plus Task 3 test `not_invited shows the invite copy and setup can be retried`.
3. **Plugin updates.** After a version bump the bundle must match the source. A stale committed bundle would silently ship old helper code. → Task 3 test `committed bundle matches a fresh build`.
4. **An admin invites a GitHub username that doesn't exist, or the GitHub API is rate-limited.** Expected: a clear message and no invite row. → Task 2 test `unknown GitHub username shows a message and adds nothing`.
5. **Integration tests against the hosted project while invite-only is on.** They must not quietly open the gate on production. → Task 1 test `remote integration setup refuses while invite_only is on`.

## Decisions this plan makes (beyond the spec)

- **Helper runtime:** a committed Bun bundle instead of compiled binaries for v1 (owner decision). Compiled binaries (~110 MB each) come with a public launch.
- **Invite gate:** it lives in `claim_nickname` (profile creation), not in sign-in. A Supabase auth user without a profile can do nothing anyway, since every RPC needs a profile.
- **GitHub username → id:** the admin's browser asks the public GitHub API, so the backend needs no outbound call and no token.
- **No GitHub Actions CI** in this plan; the test commands stay local. CI can follow once the repo is public.
- **No icon:** `icon` matters only for Anthropic's directory listing, which this beta doesn't target.

## Owner decision before going public (not a task)

Every commit so far is authored with the owner's personal email (the address in the git config). A public repo exposes that address. The options:
- **Accept it.**
- **Rewrite history** to a GitHub noreply address before publishing, with `git filter-repo --mailmap` and a force-push to `main`. This is destructive and the owner runs it.
- **Use a noreply address for future commits only.**
